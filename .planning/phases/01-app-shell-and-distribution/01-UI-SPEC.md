| Property | Value |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, stepper connector line thickness |
| sm | 8px | Compact element spacing, button icon-to-label gaps |
| md | 16px | Default element spacing, card padding, section gaps |
| lg | 24px | Section padding, welcome screen content gaps |
| xl | 32px | Layout gaps, page-level vertical rhythm |
| 2xl | 48px | Major section breaks, welcome screen top/bottom padding |
| 3xl | 64px | Page-level vertical spacing (welcome hero area) |

Exceptions: Stepper step circles are 28px (7 Tailwind units) -- not a spacing token, a component sizing choice. Touch targets on stepper buttons are 44px minimum (accessible tap target).

**Source:** Default 8-point scale. Stepper circle size from RESEARCH.md stepper pattern.

## Typography

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 16px | 400 (regular) | 1.5 | `text-base font-normal leading-normal` |
| Label / Small | 14px | 400 (regular) | 1.4 | `text-sm font-normal leading-snug` |
| Heading | 20px | 600 (semibold) | 1.3 | `text-xl font-semibold leading-tight` |
| Display | 28px | 600 (semibold) | 1.2 | `text-2xl sm:text-3xl font-semibold leading-none` |

**Weights used: 2 total** -- 400 (regular) and 600 (semibold). No other weights permitted in Phase 1.

**Usage rules:**
- Display: welcome screen title only ("ErasureKit" hero heading)
- Heading: section titles, step titles, page headings, brand text in header
- Body: paragraph text, descriptions, bullet lists, privacy statement
- Label: stepper step labels, button text, navigation items, metadata

**Source:** D-09 (system font stack). Sizes are defaults appropriate for a privacy tool targeting non-technical EU adults -- 16px body ensures readability. Weights consolidated to 2 (regular + semibold) per design constraint.

| Danger | `#EF4444` (red-500) | `--ek-danger` | Destructive actions, error states |

### Accent Reserved For (explicit list)

The accent color `#0EA5E9` is used ONLY on these elements:
1. **Primary CTA buttons** ("Get Started", "Resume Campaign") -- solid background
2. **Active stepper step** -- filled circle and highlighted label
3. **Completed stepper step checkmarks** -- filled circle background (uses `--ek-success` for the check icon itself, `--ek-primary` for the circle fill is also acceptable)
4. **Stepper connector lines** between completed steps -- solid accent line
5. **Theme toggle icon** when hovered
6. **"ErasureKit" brand text** in the header

Accent is NOT used on: body text, card backgrounds, borders, dividers, hamburger menu items, footer text, or placeholder content.

**Source:** D-07, D-08 (CONTEXT.md). Dark mode surface adjusted from D-07's `#1E293B` to `#0F172A` for the dominant 60% background -- `#1E293B` serves as the 30% secondary surface. This provides better contrast hierarchy.

## Component Inventory (Phase 1)

**Welcome screen:** The primary focal point is the Display heading ("Take back your data") and the CTA button ("Get Started" / "Resume Campaign"). These two elements form the visual anchor. The heading draws the eye with the largest type size (28px semibold), and the CTA button anchors the action with an accent-colored solid background, full-width on mobile. All other welcome screen content (body text, bullet points, privacy statement) is supporting context that leads the user's eye from heading to CTA.

## Interaction Patterns

### Stepper Navigation (D-01, D-02, D-03)

- All 4 steps are clickable at all times (free jumping, no locks)
- Clicking a step sets it as current page and updates stepper visual state
- Completed steps show checkmark; current step shows highlighted circle; future steps show dimmed number
- On mobile (< 640px): step labels are hidden, only numbered circles visible
- Stepper occupies the space directly below the header, sticky along with header

### Theme Toggle (D-06)

- Single click toggles between dark and light mode
- Preference persisted to `localStorage` under key `ek-theme`
- Default is dark mode when no preference stored
- Toggle applies `.dark` class on `<html>` element
- Transition: `transition-colors duration-200` on `<body>`

### Hamburger Menu (D-04)

- Click hamburger icon to open slide-in panel from right
- Click backdrop overlay or close button to dismiss
- Menu items: "Legal Reference", "Escalation", "About"
- Each item navigates to the corresponding page and closes the menu
- Transition: slide in from right, 200ms ease-out

### Welcome Screen (D-12, D-13)

- Shown by default when no step is active (initial page load)
- If `localStorage` contains cached campaign data: CTA reads "Resume Campaign" and navigates to last active step
- If no cached data: CTA reads "Get Started" and navigates to Step 1 (Identity)
- CTA button has hover scale-up micro-animation (CSS only, `hover:scale-[1.02]`, 150ms ease-out)

## Accessibility

| Concern | Implementation |
|---------|---------------|
| Stepper semantics | `<nav aria-label="Progress">` wrapping stepper. Active step has `aria-current="step"`. |
| Theme toggle | `aria-label="Switch to light mode"` / `"Switch to dark mode"` (dynamic). |
| Hamburger menu | `aria-expanded="true/false"` on trigger. `aria-label="Menu"`. Focus trap inside open panel. Escape key closes. |
| Color contrast | All text meets WCAG AA (4.5:1 for body text, 3:1 for large text). Accent `#0EA5E9` on `#0F172A` = 5.4:1 (passes). White on accent `#0EA5E9` = 3.8:1 (use bold/large text or add text shadow for small text on accent buttons). |
| Focus indicators | 2px accent ring with 2px offset on all interactive elements. `focus-visible:ring-2 focus-visible:ring-sky-500 focus-visible:ring-offset-2`. |
| Reduced motion | Wrap transitions in `@media (prefers-reduced-motion: no-preference)`. Users with reduced motion see instant state changes. |
| Keyboard navigation | Tab order: brand > theme toggle > hamburger > stepper steps > main content > footer links. All interactive elements reachable via Tab. |

## CSS Custom Properties Contract

These are the design tokens that MUST be declared in both dev-mode `<style>` blocks and production `styles.css`:

```css
/* Dark mode values (default) */
:root {
  --ek-primary: #0EA5E9;
  --ek-accent: #06B6D4;
  --ek-surface: #0F172A;
  --ek-surface-alt: #1E293B;
  --ek-text: #F8FAFC;
  --ek-text-muted: #94A3B8;
  --ek-success: #22C55E;
  --ek-warning: #F59E0B;
  --ek-danger: #EF4444;
  --ek-border: #334155;
}

/* Light mode values */
.light {
  --ek-surface: #F8FAFC;
  --ek-surface-alt: #F1F5F9;
  --ek-text: #0F172A;
  --ek-text-muted: #64748B;
  --ek-border: #E2E8F0;
}
```

**Note:** The RESEARCH.md pattern uses `.dark` class toggling with `dark:` Tailwind variants. The CSS custom properties above are supplementary for values referenced directly (e.g., `bg-[var(--ek-surface)]`). The implementation can use either Tailwind `dark:` utilities OR CSS custom property switching -- both achieve the same result. The executor should choose the approach that keeps the codebase simplest. The recommended approach: use Tailwind's `dark:` utilities for standard slate colors and CSS custom properties for the accent/semantic colors only.
