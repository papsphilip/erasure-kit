  <action>
    The user must complete these steps in external dashboards. Claude cannot do these -- they require browser-based authentication to Cloudflare and Resend accounts.

    **Step 1 -- Resend domain setup:**
    1. Go to Resend Dashboard -> Domains -> Add Domain
    2. Enter: `erasurekit.uk`
    3. Select region: `eu-west-1` (per D-16 for GDPR data residency)
    4. Resend will show 2-3 DNS records to add (SPF TXT record, DKIM CNAME records, optional DMARC)

    **Step 2 -- Cloudflare DNS records:**
    1. Go to Cloudflare Dashboard -> erasurekit.uk -> DNS -> Records
    2. Add the SPF TXT record from Resend (typically: `v=spf1 include:amazonses.com ~all` or similar)
    3. Add the DKIM CNAME records from Resend (typically 3 CNAME records)
    4. Optional: Add DMARC TXT record: `_dmarc.erasurekit.uk` -> `v=DMARC1; p=none; rua=mailto:erasurekit@proton.me`
    5. Wait for Resend Dashboard to show domain status as "Verified" (may take 1-30 minutes)

    **Step 3 -- Resend API key:**
    1. Go to Resend Dashboard -> API Keys -> Create API Key
    2. Name: `ErasureKit Worker`
    3. Permission: `Full access` (or `Sending access` if available)
    4. Copy the key (starts with `re_`)
    5. Share the key value with Claude so it can be set as a wrangler secret

    **Step 4 -- Cloudflare KV namespace:**
    1. Go to Cloudflare Dashboard -> Workers & Pages -> KV -> Create a namespace
    2. Name: `erasurekit-relay`
    3. Copy the namespace ID (a hex string like `abc123def456...`)
    4. Share the namespace ID with Claude so it can update wrangler.jsonc
  </action>
  <resume-signal>Provide: (1) Resend API key, (2) KV namespace ID, (3) confirm domain is verified in Resend dashboard</resume-signal>

  <action>
    After the user provides the KV namespace ID and Resend API key:

    **1. Update `worker/wrangler.jsonc`:**
    Replace the placeholder KV namespace ID with the real one provided by the user.

    **2. Set the Resend API key as a wrangler secret:**
    ```bash
    cd worker && echo "<RESEND_API_KEY>" | npx wrangler secret put RESEND_API_KEY
    ```
    (Replace `<RESEND_API_KEY>` with the actual key provided by the user.)

    **3. Deploy the Worker:**
    ```bash
    cd worker && npx wrangler deploy
    ```

    **4. Verify deployment with health check:**
    ```bash
    curl -s https://api.erasurekit.uk/nonexistent | jq .
    ```
    Expected: `{ "success": false, "error": { "code": "NOT_FOUND", "message": "Unknown endpoint" } }`

    **5. Verify CORS preflight:**
    ```bash
    curl -s -X OPTIONS https://api.erasurekit.uk/send -H "Origin: http://localhost" -H "Access-Control-Request-Method: POST" -I
    ```
    Expected: 204 status with `Access-Control-Allow-Origin: *` header.

    **6. Test live email sending:**
    Send a test email to the project email (erasurekit@proton.me) to verify end-to-end:
    ```bash
    curl -s -X POST https://api.erasurekit.uk/send \
      -H "Content-Type: application/json" \
      -d '{
        "to": "erasurekit@proton.me",
        "subject": "ErasureKit Relay Test",
        "encryptedBody": "VGhpcyBpcyBhIHRlc3QgZW1haWwgYm9keQ==",
        "wrappedKey": "dGVzdC13cmFwcGVkLWtleQ==",
        "iv": "dGVzdC1pdi0xMjM=",
        "tempAddress": "t3st0001",
        "publicKey": {}
      }' | jq .
    ```
    Expected: `{ "success": true, "data": { "emailId": "...", "tempAddress": "t3st0001@erasurekit.uk" } }`

    Note: The encryptedBody/wrappedKey/iv values above are dummy base64 strings. The Worker passes them through to Resend as the email HTML body. This is intentional -- the Worker does not decrypt, it just relays. Real encryption happens in the browser (Plan 02's crypto module). This test verifies the Worker -> Resend -> inbox pipeline works.

    **7. Verify the test email arrived:**
    Check erasurekit@proton.me inbox for the test email. It should arrive from `t3st0001@erasurekit.uk`.

    **8. Clean up test temp address from KV:**
    ```bash
    cd worker && npx wrangler kv key delete --binding KV "addr:t3st0001"
    ```
